# 02 Build Systems

Source: https://arxiv.org/abs/1802.05365

## Paper Context

The paper decomposes build systems into reusable design choices. It separates concerns such as dependency structure, task execution, rebuilding strategy, caching, and how a scheduler decides what to rebuild.

## Figure Intent

Show a build graph with tasks and artifacts, plus the build-system machinery that observes dependencies and updates a store. The figure should communicate a build system as more than a linear compile pipeline.

## Concepts To Show

- Source artifacts
- Generated artifacts
- Task nodes
- Dependency edges
- Scheduler
- Store/cache
- Dirty or changed input
- Rebuilt output

## Relationships

Artifacts flow through tasks according to dependency edges. A changed input invalidates dependent tasks. The scheduler consults dependencies and store/cache state before rebuilding outputs.

## Chinese Labels

Include labels such as `依赖图`, `调度器`, `缓存`, `增量重建`.

## Design Notes

Use a small DAG for task dependencies and place scheduler/store as supporting infrastructure below or beside the DAG. Avoid making the whole diagram a simple left-to-right pipeline.
